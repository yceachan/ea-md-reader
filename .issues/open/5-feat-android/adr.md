# ADR-005：复用阅读界面，新增 Android 文档端口

状态：拟定路线，未实施。需求和证据以 [raw issue](issue.md) 为唯一来源。Android 技术选择尚未完成运行验证。本文维护运行时取舍与平台边界。

## 运行时路线

推荐用 Capacitor 承载现有 React/Vite 阅读界面。Capacitor 在 Android WebView 中运行前端，并通过原生插件调用 Java/Kotlin 能力。应用不继续把 Electron 打包成 Android 程序，也不把 Node 注入文档页面。[Capacitor Android 文档](https://capacitorjs.com/docs/android)支持此路线。

另一个候选是 Kotlin 原生外壳加 WebView。它也能复用前端，但本项目需要自行管理原生桥、资源服务、生命周期和构建入口。先验证 Capacitor 能否满足文档授权和 HTML 隔离，再决定是否需要这个替代路线。首版不重写整套阅读 UI 为原生组件。

共用范围是 Markdown 渲染、排版、目录树、多标签语义、通知和覆盖层行为。平台范围是文件授权、窗口/返回键、文档接收、网页链接、设置存储、页面资源、查找与生命周期。Android 删除编辑器打开能力。具体工具版本由 route 维护，ADR 不再复制依赖矩阵。

## 应用接口与文档身份

沿用 [ADR-001](../../closed/1-feat-platform-interface/adr.md) 的方向：应用声明能力，各端实现。桌面端使用 Electron，Android 端使用原生插件。UI 调用应用能力接口，不直接依赖 `window.emd` 的 Electron 注入存在。

文档引用需要支持桌面路径与 Android 文档 URI。共享 UI 使用不透明的文档标识、显示名称和工作区关系。平台负责解析资源、读取 bytes 和定位父子节点。不能把 `content://` 通过字符串处理伪装成普通路径。

现有 Node `files.cjs` 继续作为桌面实现。UTF-8、原始 bytes 快照、只读和更新事件的语义共享。Android 在自己的端口实现文档提供器读取与身份检查，不增加没有实际差异的通用文件框架。

界面按实际能力提供操作。桌面窗口控制在 Android 不显示。Android 不提供 `right-dock` 启动设置，系统管理其应用窗口。共用 `setting.toml` 的文件格式，Android 将文件放在应用私有目录。Android 不展示或执行桌面编辑器分区，桌面存储约定仍归 ADR-004。

## 文件、工作区与资源

Android 文件入口使用系统文档选择器读取文件，目录选择器授权工作树。只持久化系统实际授予的权限。收到单文件 Intent 时先提供文件阅读，访问相邻文件或图片时再取得目录授权，不请求整个存储空间权限。

原生端以文档提供器身份枚举树和读取资源，保留授权边界。另存为使用新文档选择器写入当前成功快照的原始 bytes。Reader 不直接覆盖输入文档。文件 MIME 和显示名分别检查，不能只依赖提供器报告的扩展名。

相对图片与链接由文档端口解析到已授权目标。前端通过受限资源标识获取它们，资源 URL 的生命周期随文档释放。应用自带 JS、CSS、字体和 WASM 必须打包到本地，离线启动不依赖外部 CDN。[Android 本地内容加载说明](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)提供 HTTP(S) 资源加载的实现方向。

## HTML 与原生桥

Markdown 继续使用现有清理流程。可执行脚本的自包含 HTML 在独立、没有应用原生桥的 WebView 中预览。可信阅读界面拥有必要插件桥，用户 HTML 页面不拥有该桥。两个视图之间仅传应用控制的加载与关闭动作，不代理文档的任意消息。

独立 HTML 预览继续限制导航、网络、文件访问和页面权限，并保留自包含脚本交互。必须用恶意 HTML 验证无法调用文档、设置或其他原生能力，不能只凭不同 URL 或 iframe sandbox 认定隔离成立。风险依据见 raw issue 的 B5.1。

在 Capacitor 中建立无桥预览及安全资源加载是首个原型门槛。若原型无法保持现有交互与隔离边界，先讨论原生预览方案，再进入完整 Android 实施。

## 交互与生命周期

使用条目 4 的共享窄屏面板模式。触摸用户通过按钮和长按菜单执行操作，不要求中击或右键。手机布局不保留桌面的最小宽度限制。软键盘、安全区域和分屏变化都按实际视口重新布局。

Android 返回键先关闭菜单和覆盖层，再按产品约定处理阅读页面。宿主的返回动作传给共享 UI，由同一状态处理。进程被系统回收后恢复文档标识与阅读位置，并重新检查权限，不保存无效授权作为成功状态。

Android 不增加编辑器配置、编辑器菜单、编辑 Intent 或对应原生接口。长按菜单保留阅读、工作树重载和适用文件操作，不提供“在配置编辑器中打开”或编辑器“打开方式”。共享代码按能力省略入口，原生端也不实现该操作。

返回 Reader 前台时核对已登记文档，提供器支持变化通知时可增加通知驱动更新。它处理文件变化与进程恢复，不依赖编辑会话。条目 3 的编辑器验收不适用于 Android，桌面端验收保持。
