# ADR-004：统一启动设置与平台布局执行

状态：拟定，未实施。已确认的配置格式与默认值见 [raw issue](issue.md)。本文维护启动设置、参数、平台执行和面板模式。编辑器描述仍由 [ADR-003](../3-feat-external-editor/adr.md)维护。

## 共用设置来源

应用只维护一个 `setting.toml`。桌面文件位于 `app.getPath('userData')` 下。主进程统一读取和写入，渲染层通过受限接口读取设置或提交修改。TOML 的解析与序列化实现作为必要依赖，在实施时选择并锁定。

启动布局字段属于本文，格式为：

```toml
[startup]
layout = "default"
```

`startup.layout` 只接受 `default` 和 `right-dock`。编辑器字段属于 ADR-003，使用同一设置文件中的独立分区。任何设置更新必须保留另一个分区，不由两个功能分别整文件覆盖。文件写入继续采用临时文件替换。

文件不存在或启动布局字段尚未配置时，使用已确认的 `default`。TOML 损坏、字段类型错误或非法枚举值必须报告错误，不能伪装成缺省值。应用不覆盖损坏文件。首版不增加布局历史、屏幕偏好列表或自动记忆窗口位置。

## 启动参数与优先级

生效值依次取命令行 `--layout=...`、保存的 `startup.layout`、出厂 `default`。命令行不改写 TOML。解析与文件参数在同一入口完成，保留 `--` 字面参数语义，并区分 Electron 自身参数。

布局设置作用于下次新主窗口创建。当前窗口不因保存设置而跳动。第二实例只按既有机制打开文件，启动布局参数不搬动已存在的窗口。需要即时重新布局的动作不在首版范围。

| 布局 | 窗口行为 | 初始面板 |
| --- | --- | --- |
| `default` | 普通窗口，沿用当前 1180×850 的请求尺寸及系统普通放置行为 | workspace 与 TOC 隐藏 |
| `right-dock` | 目标屏幕工作区右边，宽度为应用最小宽度，工作区全高度 | workspace 与 TOC 隐藏 |

目标屏幕按启动前活动窗口确定。用户已确认没有活动窗口时使用 KWin 活动屏幕。目标工作区排除任务栏等保留区域。当前应用最小宽度为 620，后续调整最小宽度时，右停靠使用同一来源，不另存第二个数值。

## 平台执行

沿用 [ADR-001](../../closed/1-feat-platform-interface/adr.md)：应用定义启动布局语义，平台实现取得启动上下文并执行。平台返回实际几何和执行结果。主进程把界面需要的当前屏幕工作区信息传给渲染层。

KDE Wayland 由 KWin 执行定位。KDE 模块在 Reader 取得焦点前捕获活动窗口所在输出。按工作区矩形 `(x, y, width, height)` 和最小宽度 `m`，目标矩形为 `(x + width - m, y, m, height)`。使用逻辑坐标，不在应用重复乘设备像素比。

KWin 按固定窗口身份与本次请求匹配主窗口，排除文件对话框及其他 Electron 窗口。它只应用一次初始几何，用户之后的移动和缩放不触发重排。当前 KWin 允许写入 `frameGeometry`。[KWin 6.7.5 窗口源码](https://github.com/KDE/kwin/blob/v6.7.5/src/window.h)支持这一执行方向。

KWin 集成必须接收本次生效布局。不能安装一个无条件把 Reader 拉到右边的全局规则，否则 `default` 无法成立。加载、请求关联、结果回传、超时及清理先做小范围原型。原型完成后再固定为随应用管理的 KDE 实现。

拟定优先验证每次启动加载有限寿命 KWin 脚本的方案。脚本在窗口创建前捕获上下文，匹配并完成本次请求后清理。KWin 提供脚本加载与卸载接口，但本工程尚未验证该流程。[KWin 6.7.5 脚本接口](https://github.com/KDE/kwin/blob/v6.7.5/src/scripting/scripting.h)是原型依据。

原型若证明常驻脚本更合适，必须先讨论其配置传递和用户级安装生命周期，再修改本决策。不调用模拟全局快捷键，也不操作与当前请求无关的活动窗口。未加载 KWin 集成或执行失败时，启动错误要可见，不能静默显示普通窗口并宣称停靠成功。

X11、Windows、macOS 的位置和目标屏幕取得由对应平台能力实现。共享代码不默认使用鼠标屏幕，因为用户已选择活动窗口屏幕。Android 不使用桌面窗口定位，差异由 [ADR-005](../5-feat-android/adr.md)维护。

## 面板展示模式

用户开关状态与展示模式分开保存。首次两个开关都为关闭。`ResizeObserver` 只计算当前适合的展示方式，不因窗口变宽而改变用户开关意图。模式不以操作系统或设备名称判断。

workspace 的停靠边界沿用 F4.3 的公式。低于该边界时使用覆盖层。TOC 在不超过当前屏幕工作区半宽时使用覆盖层；超过半宽也必须满足正文与停靠面板的实际空间条件，才允许占用正文旁的空间。

工作区尺寸和渲染层可用宽度换算到一致的 CSS 坐标。应用缩放、系统缩放和边框分别处理，不能拿物理屏幕宽度与 CSS 容器宽度直接比较。移动到另一屏幕后按新屏幕重算展示模式，不自动重新停靠窗口。

覆盖层依附阅读工作区，workspace 从左侧呼出，TOC 从右侧呼出。它们脱离正文布局流，不改变阅读容器宽度。覆盖层没有面板拖拽分隔条，并具有遮罩、关闭按钮、焦点限制和焦点恢复。遮罩覆盖 HTML iframe，防止点击穿透。

TOC 选中有效锚点并完成定位后收起。目录分支展开不收起。workspace 成功打开文件后收起，失败时继续显示错误。打开一个覆盖层时关闭另一个。窗口跨模式边界时重新计算展示方式，并保证停靠空间和覆盖层只出现一份。

## ADR 对齐与讨论项

D4.1 已确认：使用一个 `setting.toml`。ADR-003 的“单独编辑器配置文件”改为共同设置来源，编辑器数据结构归属不变。

D4.2 已确认：出厂布局为 `default`。它保留普通窗口请求尺寸，不新增上次窗口恢复。两个面板默认隐藏的要求继续适用。

D4.3 待原型验证：KDE 布局请求传递及脚本生命周期。验证范围是一次新主窗口，不能扩大到全局窗口管理规则。

D4.4 已确认：没有活动窗口时使用 KWin 活动屏幕。工作区小于应用最小宽度或最小高度时，明确报告布局失败。目标输出不存在或在执行期间移除也按执行失败处理，不悄然换到另一屏。错误处理不退出可用于阅读的应用窗口，也不把普通放置结果标为成功停靠。

D4.5 拟定：Android 不显示桌面停靠选项。移动端布局只根据其视口和条目 4 的覆盖层规则。Android 技术路线仍为规划，尚未成为实施承诺。
