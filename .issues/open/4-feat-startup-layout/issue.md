# 4：可配置启动布局与窄屏面板覆盖层

状态：4.0 的 KDE 原型核心路径已实测，完整设置与覆盖层功能待前置阶段完成。证据见 [probe-kde](artifacts/probe-kde.md)。 来源：本轮用户请求与后续讨论。本文维护需求、取证和验收。代码基线见[条目 1](../../closed/1-feat-platform-interface/issue.md)。

## 原始请求与已确认调整

> feat4 ： 默认启动size ： 聚焦screnn 的右半分屏，显示workspace，隐藏toc； 改动toc显示/隐藏逻辑：在窄屏模式(半屏宽度以下) ，toc为呼出式overlay，不影响正文排版，选中锚点后自动收起 。在更窄的模式下（当前自动隐藏workspace 的宽度，实际等价未来移动端的ui布局），titlebar 上 show workspace panel 的行为也变成呼出overlay式的

用户随后确认“聚焦屏幕”为启动前活动窗口所在屏幕。用户又调整启动行为：“启动size 改成右停靠全高度，app 的最小宽度(workspace 和toc 都默认隐藏吧)”。右停靠因此改为最小宽度窗口，原始右半屏尺寸要求不再使用。两个面板的启动可见状态也改为隐藏。

用户要求沿用统一启动参数路线，并让设置菜单配置 `default` / `right-dock`。参数入口拟为 `emd --layout=right-dock 文件.md`，目前尚未实现。参数表达应用语义，平台实现执行布局。

用户最后明确：“共用一个setting.toml”，未配置时选择“default（普通窗口布局）”。`default` 表示当前普通窗口布局，`right-dock` 表示可选右停靠布局。前面讨论的“右停靠作为未配置默认值”已被这次选择替换。

## 需求

TOC 是 Markdown 的目录面板。停靠面板占用正文旁的空间。覆盖层显示在正文上方，不改变正文排版。

| 编号 | 需求 |
| --- | --- |
| R4.1 | 设置菜单提供启动布局 `default` 和 `right-dock`，并保存到共用 `setting.toml`。 |
| R4.2 | 未配置采用 `default`。两种启动布局均默认隐藏 workspace 和 TOC。 |
| R4.3 | `default` 保留普通窗口行为。`right-dock` 在启动前活动窗口所在屏幕的工作区右边停靠，使用应用最小宽度和工作区全高度。 |
| R4.4 | 应用提供 `--layout=default` / `--layout=right-dock`。本次命令行值覆盖已保存设置，不改写设置文件。 |
| R4.5 | 启动布局只在新主窗口创建时应用。第二次启动打开文件、窗口恢复和用户调整尺寸不重新强制布局。设置变更作用于下次启动。 |
| R4.6 | 窗口不超过当前屏幕工作区半宽时，TOC 为右侧覆盖层。选中有效锚点后自动收起。 |
| R4.7 | 达到当前 workspace 自动隐藏的窄宽度范围时，顶栏 workspace 按钮呼出左侧覆盖层，不挤压正文。 |
| R4.8 | 覆盖层有关闭按钮、遮罩与 Esc 关闭行为。同一时刻只打开一个面板覆盖层。正文滚动和 HTML 隔离继续有效。 |
| R4.9 | 平台模块处理窗口定位、显示器坐标和系统限制。界面共享面板规则，不调用 KWin 或系统命令。 |

面板初始隐藏不等于不可使用。没有打开文档时，设置入口仍可用。工作区尚无根目录时显示明确空状态，不扫描任意目录。HTML 不提供 Markdown TOC。

## 现状与风险

F4.1：`electron/main.cjs:111` 固定窗口为 1180×850，最小宽度 620，最小高度 440。没有启动布局设置、目标屏幕选择或参数解析。`electron/files.cjs` 只筛选文件参数，不能用忽略未知旗标代替正确的布局参数解析。

F4.2：`src/App.tsx` 初始化两个面板为显示。`ResizeObserver` 根据宽度改变显示状态，所以只修改初始布尔值仍可能在第一次测量时自动打开面板。当前 TOC 展开会占用正文宽度，选择锚点不会关闭它。

F4.3：当前 workspace 自动隐藏边界为左面板宽度 + 520 CSS px + 5 CSS px。默认左面板 240px 时，边界为 765 CSS px。这个边界随面板宽度变化，不能误当成固定的 765 物理像素。

F4.4：当前环境为 KDE Wayland，KWin 6.7.5。Electron 在 Wayland 不支持 `setPosition`，也不支持获取全局鼠标坐标。KDE 的定位需要窗口管理器参与。[Electron 窗口说明](https://www.electronjs.org/docs/latest/api/browser-window#winsetpositionx-y-animate)和[屏幕说明](https://www.electronjs.org/docs/latest/api/screen#screengetcursorscreenpoint)记录这些限制。

F4.5：原生右半屏贴靠会得到半屏宽度，不能直接实现 620px 的右停靠窗口。KWin 实现必须根据工作区边界设置所需几何，并保证普通布局不受同一规则影响。

F4.6：现有 UI 测试强制 `--ozone-platform=x11`。它们可以验证应用布局，但不能证明 KDE 原生 Wayland 的焦点屏幕选择和窗口位置。

## 验收条件

| 编号 | 完成证据 |
| --- | --- |
| A4.1 | 首次无设置启动使用 `default`。设置可切换并持久保存两种值。编辑器设置与启动布局互不丢失。 |
| A4.2 | 两种启动布局都隐藏 workspace 和 TOC。第一次宽度测量、缩放或窗口变化不擅自重新打开它们。 |
| A4.3 | `right-dock` 使用启动前活动窗口的屏幕，窗口右边、顶部和底部与该屏幕工作区对齐，宽度等于应用最小宽度。边界取整允许 1 个逻辑像素差值。 |
| A4.4 | 命令行覆盖仅对本次新窗口有效。错误值明确失败，`--` 后的字面文件参数仍正确。第二次启动不搬动已有窗口。 |
| A4.5 | TOC 覆盖层开关前后正文边界和段落换行不变。选锚点后正文定位正确，TOC 收起。折叠目录分支本身不关闭覆盖层。 |
| A4.6 | workspace 窄模式呼出不改变正文尺寸。成功打开文件后收起，失败时保留面板与错误信息。根目录重载仍可使用条目 2 的菜单。 |
| A4.7 | 遮罩、关闭按钮和 Esc 都关闭覆盖层，焦点恢复到触发按钮。覆盖层与 HTML iframe 相邻时不发生点击穿透。 |
| A4.8 | 跨宽度边界时，展示模式与用户开关状态分别处理，不残留停靠空位或分隔条，不让两个覆盖层同时显示。 |
| A4.9 | KDE Wayland 原生验证覆盖双屏、负坐标、缩放、任务栏、窗口身份和普通布局不受影响。无活动窗口时使用 KWin 活动屏幕。工作区尺寸不足时明确报告布局失败。共享 UI 测试在桌面 CI 通过。 |

用户已确认：无活动窗口时使用 KWin 活动屏幕，屏幕工作区小于应用最小尺寸时明确报告布局失败。目标屏幕在执行期间移除时同样不能被标记为成功停靠。决策见 [ADR-004](adr.md)，步骤见 [route](route.md)。
