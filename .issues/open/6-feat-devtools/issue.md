# 6：F12 与文件菜单开发者控制台

状态：需求已整理，实施未开始。日期：2026-10-06。来源：用户新增请求。本文维护需求、取证和验收。架构见 [ADR-006](adr.md)，执行见 [route](route.md)。

## 原始请求

> feat6 ，提供F12 快捷键/ file menu  icon 下拉菜单，跟setting 的统一分割线网格子处，打开开发者控制台便于 debug样式。

文件菜单按顶栏 file menu 图标的下拉菜单理解。“跟 setting 的统一分割线网格子处”按同一个菜单分隔组理解，该组包含“设置…”和“开发者控制台”。顶栏设置图标继续调用同一设置动作，不增加第二套设置界面。

移动端删除编辑器功能的更正只限制条目 3、5 的外部编辑能力。用户已另行确认本条目首期覆盖桌面端，Android 使用设备远程调试，不提供应用内控制台菜单。该范围由本条目的确认决定。

## 需求

| 编号 | 需求 |
| --- | --- |
| R6.1 | 按 F12 打开当前 Reader 界面的开发者控制台，便于检查 DOM、CSS 和运行错误。 |
| R6.2 | 文件菜单提供“开发者控制台”，显示 F12 提示，与“设置…”放在同一分隔组。 |
| R6.3 | 快捷键与菜单调用同一个语义命令。无文档时也可调试欢迎界面和布局。 |
| R6.4 | 已打开控制台时复用，不建立重复控制台窗口。手动关闭后仍可再次打开。 |
| R6.5 | 目标是 Reader 的应用界面，保持现有文档隔离、只读与受限原生接口。 |
| R6.6 | 首期控制台入口覆盖 Electron 桌面端。Android 使用设备远程调试，不加入应用内控制台。 |

首版只提供用户主动打开的调试入口，不默认打开控制台。没有请求远程调试监听端口、日志服务或开发模式设置。

## 现状证据

F6.1：`electron/main.cjs` 的键盘处理已有 F11、文件菜单及文档命令，没有 F12。应用没有开发者控制台动作，也没有对外暴露 DevTools IPC。

F6.2：`src/App.tsx` 的文件菜单目前有打开、另存为、关闭标签和退出。条目 2 规划顶栏设置入口，条目 4 规划设置数据。需要给文件菜单接入同一个设置动作，再加入本条目的调试动作。

F6.3：Electron 的 `webContents.openDevTools` 提供开发者工具入口，可指定独立窗口模式。功能必须绑定主窗口的 webContents。[Electron DevTools API](https://www.electronjs.org/docs/latest/api/web-contents#contentsopendevtoolsoptions)是桌面实现依据。

F6.4：Android 使用 WebView 运行时规划，没有 Electron webContents。设备远程调试可检查 WebView，但它不能直接等同于 Reader 内的控制台菜单。[Android WebView 调试说明](https://developer.android.com/develop/ui/views/layout/webapps/debugging)说明原生调试方向。

Android 远程调试准备由条目 5 的设备工具链负责。它不纳入 A6.1 的桌面 F12 验收，也不把远程检查伪装成应用内菜单。
