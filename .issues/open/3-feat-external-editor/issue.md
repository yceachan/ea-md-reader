# 3：配置外部编辑器并自动重读

状态：3.0 的 Linux 编辑会话探测完成，macOS 与 Windows 原生探测仍待验证。完整功能待共用设置入口。证据见 [probe-editor](artifacts/probe-editor.md)。 来源：本轮用户请求。源码证据来自当前未提交工作区，取证基线见[条目 1](../../closed/1-feat-platform-interface/issue.md)。本文维护本条目的需求、证据和验收条件。

## 原始请求

> 三.feat 1: setting 可配置默认markdown/html编辑器。侧边栏/标签栏中击文件/ 右键菜单->在配置编辑器中打开/打开方式--- 则可通过编辑器打开修改文件。关闭编辑器后，只读 reader自动重新载入文件。

用户随后更正：“tabbar 中击保持跟浏览器一样的关闭行为, workspace 中级才是跟dolphin 一样的次选打开方式打开 (即app里配置的`使用配置编辑器打开``)”。用户还明确移动端删除“在编辑器打开”功能。原始请求中“标签中击编辑”的解释不再使用。

本条目适用于桌面端。默认编辑器按 Markdown 和 HTML 分别配置。workspace 文件中击与“在配置编辑器中打开”调用对应类型的编辑器。标签中击保持关闭。“打开方式…”提供本次选择其他编辑器的入口，是否设为默认由明确操作决定。

## 需求

| 编号 | 需求 |
| --- | --- |
| R3.1 | 桌面设置中配置默认 Markdown 编辑器与默认 HTML 编辑器，存入共用 `setting.toml`，重启后仍保留。 |
| R3.2 | workspace 文件中击，在配置编辑器中打开原文件。标签中击保持关闭行为，Reader 保持只读。 |
| R3.3 | 文件与标签右键提供“在配置编辑器中打开”和“打开方式…”。操作对象是被点击文件，即使它不是活动标签。 |
| R3.4 | 外部编辑会话结束后，Reader 自动重读对应文件，更新已有标签的内容。 |
| R3.5 | 保留标签身份、活动标签和有效工作区根目录。HTML 重读取得新的预览版本，Markdown 更新正文和目录。 |
| R3.6 | 未配置、取消选择、启动失败、读取失败均有明确结果。Reader 不替换系统默认文件关联。 |
| R3.7 | 移动端不提供编辑器配置、中击编辑、在配置编辑器中打开或编辑器打开方式入口。 |

“打开方式…”不要求首版枚举系统全部应用。它可以通过平台文件/应用选择器选择可用编辑器。首版不新增历史编辑器列表、终端编辑器托管或任意 shell 命令功能。

## 现状证据与冲突

`src/App.tsx:204` 的标签 `onAuxClick` 在 `button === 1` 时调用 `close(tab.id)`。它符合更正后的 R3.2，实施时保留。工作区文件只处理左键及 Alt 左键，没有中击编辑入口。标签也没有文件右键菜单。

`electron/main.cjs:175` 的工作区菜单只提供在 Reader 中阅读、文件管理器和重载。项目没有编辑器配置、编辑器启动接口或编辑会话管理。`electron/preload.cjs` 和 `src/env.d.ts` 没有相应能力。

`electron/main.cjs:202` 已有按文档 id 手工重读的入口，它保留 id 并替换文档对象。`electron/files.cjs:33` 对 HTML 每次公开文档都生成新 `pageUrl`。当前工作区的 HTML 预览通过独立协议和受限 iframe 加载。这些可以作为自动重读的基础，但当前只更新手工调用的标签。

已有工作区 Alt 左键会新建标签，同一路径可能出现多个 Reader 标签。外部编辑后必须更新该路径的所有已打开标签。不能只更新活动标签，或为每次自动重读新建标签。

## 需要验证的产品边界

B3.1：启动器退出与编辑结束不是同一事件。GUI 编辑器可以复用已有进程。macOS `.app` 可以经系统命令打开。单凭启动子进程的 `exit` 不能证明用户关闭了文件或编辑器。

B3.2：编辑器可以先写临时文件，再替换原文件。只监听旧文件对象会漏掉后续保存。删除、改名、权限改变和多次连续保存也必须处理。

B3.3：任意编辑器的“关闭文件”没有通用系统事件。严格的关闭后重读需要编辑器等待模式或可验证的会话协议。无法等待的编辑器至少需要保存变化监听和 Reader 恢复焦点时重查。后者不能单独证明原始 R3.4 已完全满足。

本条目保留 R3.4 的目标。具体可支持的编辑器和关闭事件范围由后续原生探测确定，不在文档中虚构完整支持。决策边界见 [ADR-003](adr.md#编辑会话与重读)。

| 编号 | 完成证据 |

| A3.8 | 无配置时提示进入设置，启动失败不伪装成功。删除、改名、无权限、非 UTF-8 和监听失败有明确提示，最后成功快照保留。 |
| A3.9 | 关闭 Reader 标签后，完成回调不复活该标签。退出 Reader 后不遗留监听，且不会关闭用户的编辑器。 |
| A3.10 | Linux、macOS arm64/x64 与 Windows 的启动参数和编辑会话契约通过 CI。真实编辑器的等待能力单独记录，未经验证不宣称满足 R3.4。 |
| A3.11 | Android 的设置、文件菜单、workspace 与标签菜单均没有外部编辑入口，原生端也没有可调用的编辑器启动能力。 |

“严格关闭后重读”的完成判据是 A3.5 与 A3.6 的实际会话证据。若首版仅支持无法等待的系统启动方式，该部分需求仍保持未完成。
