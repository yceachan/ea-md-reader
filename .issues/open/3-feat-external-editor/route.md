# 3：编辑器配置与自动重读实施路线

状态：3.1–3.4 已实现，3.0 已有 Linux VS Code 等待探测；3.5 的 Linux 集成已验证，macOS/Windows 原生编辑器验证保留。需求与验收引用 [raw issue](issue.md)，编辑会话决策引用 [ADR-003](adr.md)。本文维护实施阶段与验证方式。

## 依赖与顺序

条目 1 提供平台能力边界和跨平台 CI。条目 2 提供设置按钮及工作区菜单布局。条目 4 维护共用 `setting.toml`。本条目仅实现桌面编辑器功能，Android 删除该能力的工作由条目 5 执行。

| --- | --- | --- |

| 3.1：定义配置和端口 | 使用条目 4 的 TOML 存储接口，实现编辑器分区与平台端口。扩展 preload、类型和校验。 | 配置读写与错误边界通过 A3.1、A3.4、A3.8。 |

## 测试边界

主进程测试使用小型可控编辑进程。它接收参数，把修改写回文件，并等待测试信号后退出。用它验证参数传递、会话结束、快照版本和资源释放。它只是契约夹具，不是“真实编辑器全部支持”的证据。

原生启动测试通过平台实现调用夹具可执行文件。macOS 应用包分发单独验证，Windows 使用本机执行方式，不依赖 `/bin/sh`。再用 3.0 选定的真实编辑器检查已有进程复用和等待语义。需要额外程序时固定来源与版本，并记录安装方法。

文件变化测试模拟直接写入、临时文件替换、连续保存、未保存退出、删除、改名、权限错误和非法 UTF-8。对同一路径打开多个标签，确认它们同时更新。对两个不同路径同时编辑，确认内容和完成事件不串到另一条路径。

Reader UI 测试覆盖设置持久化、Markdown/HTML 分别选择、workspace 文件中击、节点与标签右键、打开方式取消以及临时选择。workspace 中击只启动一次编辑。活动与非活动标签中击都正确关闭目标，编辑器没有收到请求。关闭按钮仍有效。

自动重读测试检查 Markdown 正文、目录、查找和活动标签。HTML 测试确认 iframe 取得新版本并保留隔离边界。保留现有 HTML 交互与无主进程访问的回归用例。

结束与竞态测试先启动编辑再关闭标签，随后触发保存与完成。旧标签不得复活。Reader 退出不终止外部进程。快速连续更新后，最后展示的是最新成功快照。监听失败和读取失败都必须有可观察提示。
