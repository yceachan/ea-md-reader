# 2：顶栏与工作区整理，修复标签栏滚动条

状态：2.0 尺寸取证完成，正式 UI 实现待前置接口与 F12 接入。取证证据见 [probe-layout](artifacts/probe-layout.md)。 来源：本轮用户请求。源码证据来自当前未提交工作区，取证基线见[条目 1](../../closed/1-feat-platform-interface/issue.md)。本文维护本条目的需求、证据和验收条件。

## 原始请求

> 二.UI ： 1. topicbar ui 改动 logo name Ea.Md.Reader放最最做，然后是file menu ，pannel show ， setting  ，open ，save as 这些icon ，统一用白橙svg icon； 2. workspace panel  ui ，不要这一个`workspace`-refresh icon 的grid ， 而是在pannel 空白处右键菜单提供 重新载入工作树 的功能。3. bug： 在我的hdmi屏上，tabbar 这里会出现一个滚动条，确认好容器高度和实际预览高度一致，不应出现滚动条

“topicbar”按当前顶栏 `.toolbar` 理解。“放最最做”按最左侧理解。“pannel show”按现有左侧工作区显示/隐藏操作理解。右侧目录显示操作继续保留。HDMI 指用户报告问题的外接显示器，尚无分辨率和缩放数据。

## 现状证据

`src/App.tsx:174` 把工作区按钮放在名称之前。名称是文字 wordmark，顶栏没有独立应用 logo，也没有设置入口。文件菜单、打开和另存为已经使用内联 SVG。它们使用 `currentColor`，没有统一的白橙双色情况。

`src/components/Workspace.tsx:34` 开始输出 `.sidebar-header`。其中有 `WORKSPACE` 和刷新按钮。根目录和树节点都有右键处理，`.sidebar-scroll` 的空白处没有右键处理。主进程 `electron/main.cjs:175` 的菜单依赖根目录、目标路径和活动文档，只提供阅读、文件管理器与“刷新工作区”。

`src/app.css:24` 为标签栏设置 `flex: 0 0 41px`、`overflow-x: auto` 和 `scrollbar-width: thin`。标签按钮有上下各 12px 的 padding，还有行高和 badge 的内容高度。源码没有明确设置标签栏的纵向 overflow。

当前 `.app` 使用纵向 flex。`.workspace` 已有 `min-height: 0`，`.reading-area` 使用 `height: 100%`。Markdown 的 `.document-panel` 纵向自动滚动，HTML iframe 使用 `height: 100%`。现有 UI 测试测量了横向宽度，没有专门断言标签栏和正文的纵向尺寸。

## 故障记录

B2.1 是用户报告的 HDMI 屏标签栏滚动条。本轮未启动应用，未在 HDMI 设备上复现。滚动条方向、窗口状态、标签数量、系统缩放、Electron 缩放和显示器分辨率尚未记录。

固定的 41px 与子内容高度可能冲突。横向自动溢出也可能直接产生滚动条。字体度量、显示缩放、窗口最大化及正文外层高度都需要测量。这些是排查假设，不是已确认根因。
