# 4：启动布局偏好与窄屏面板覆盖层

状态：KDE 实现已完成并关闭，2026-10-07；其他平台启动布局保持 TODO，硬件组合验证边界见 [close](close.md)。本文维护需求与验收，设计见 [ADR-004](adr.md)，实施范围见 [route](route.md)。

## 用户最新需求

> setting 设置启动 layout 偏好，两种模式，默认布局/专注阅读模式。默认布局是当前 size；专注阅读启动扫描 pwd 当前层，单文档最小宽度且隐藏双面板，多文档半屏宽度且显示工作树。在鼠标活动屏幕启动。先做 KDE，其余平台 TODO。

用户补充 Markdown 与 HTML 统一计数；零文档使用默认尺寸，无文件参数仍显示欢迎页，不自动打开文件。最新确认：默认布局双面板展开；专注模式有文档时在工作区右侧全高度停靠。设计参考为 `/home/pi/work/OsCookbook/Better Operate/Linux/ricing_codebase/fsearch_drawer/`。

这次需求替换先前的 `right-dock`、活动窗口屏幕与命令行布局方案。此前暂缓启动尺寸、交由用户配置 KWin 规则的决定已被本次实现请求更新。窄屏面板覆盖层需求继续有效。

## 验收

| 条目 | 预期 |
| --- | --- |
| 设置 | 两种模式可选择，保存在同一个 setting.toml；缺省为默认布局并展开双面板，保存只影响下次新窗口启动。编辑器与 profile 分区保留。 |
| 计数 | 只统计启动 pwd 当前层的普通文件，复用 Reader 支持的 Markdown/HTML 扩展名，大小写不敏感；子目录不计数。 |
| 零文档 | 默认尺寸、双面板关闭；无文件参数显示欢迎页。 |
| 单文档 | 应用最小宽度、双面板关闭；仍只打开显式传入的文件。 |
| 多文档 | 鼠标屏幕工作区半宽，工作树展开、TOC 关闭；无文件参数的欢迎页可从工作树打开文件。 |
| 定位 | 默认与零文档在鼠标所在屏幕居中；专注模式有文档时右侧全高度停靠。使用工作区逻辑坐标，避开任务栏保留区域；只操作本次主窗口。 |
| 生命周期 | 一次启动完成后停止监听并卸载本次脚本；第二实例、用户移动与缩放不重新强制布局。 |
| 故障 | 无法获取输出、屏幕移除、工作区不足、几何未确认或桥接失败均显示错误，不宣称成功。 |
| 面板 | 窄屏左右覆盖层不挤压正文、互斥，支持关闭、遮罩、Esc 与成功操作后收起；TOC 开关为独立吸附组件，位于面板左边缘并垂直居中，具有目录图标、TOC 标识、高光、阴影和交互反馈，不占目录内容列；折叠后保留入口。 |
| 平台 | KDE X11 与原生 Wayland 均验证，其他平台设置明确显示 TODO。 |

物理多屏鼠标切换、实际任务栏与不同设备缩放组合仍由用户实机查验；隔离环境结果不替代这些硬件覆盖。
