## 高度排查

记录显示器分辨率、系统缩放、`devicePixelRatio`、`window.innerWidth/innerHeight`、Electron zoom factor 和 BrowserWindow 内容边界。记录窗口是否最大化、查找栏是否打开及标签数。

采集 `.app`、`.toolbar`、`.tabbar`、`.tab`、`.tab-select`、`.findbar`、`.workspace`、`.reading-area`、活动 `.document-panel`、`.html-page` 和 `.statusbar` 的边界。对滚动容器采集 `clientHeight`、`scrollHeight`、`clientWidth`、`scrollWidth`、padding、line-height、flex 与 overflow 计算值。

先确认标签栏内容是否超过其可用高度。再确认滚动条是否来自标签过多。最后比较阅读区、预览与状态栏边界，排除预览容器增加外层高度的情况。只有这些数据支持具体修复时才修改 CSS。

## 行为与回归

在 `tests/reader.spec.cjs` 增加针对真实风险的 UI 断言。顶栏检查顺序和设置入口。工作区检查空白右键、新建文件后重载、目录重命名以及展开状态。不要为每个 SVG path 写镜像测试。

高度用例使用短 Markdown、长 Markdown、短 HTML、长 HTML。覆盖 1 个标签、大量标签和长文件名。覆盖查找栏、两侧面板、最小窗口、最大化与还原。断言标签栏纵向内容没有溢出，活动预览与阅读区边界一致，状态栏仍在窗口内。

大量标签用例确认横向滚动仍有效。通过语义命令切换到视区外的标签，确认它进入可视区。标签中击关闭按条目 3 的更正要求继续回归，不改成编辑入口。

缩放用例覆盖 A2.8 的范围，记录实际视口。Linux 无头环境用 Xvfb 的代表尺寸；macOS 和 Windows 记录实际内容尺寸。模拟布局通过后，HDMI 硬件复查仍单独标记“待验证”或记录实测结果。

若后续需要交付布局预览，生成一个自包含 HTML 文件。它只展示 ADR-002 的设计，不复制 raw issue 或另立路线。当前文档交付不需要预览。
