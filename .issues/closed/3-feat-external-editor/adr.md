# ADR-003：受限编辑器启动与文件快照更新

状态：按 2026-10-07 用户确认的首版范围实施。需求、产品边界与验收以 [issue](issue.md) 为唯一来源。本文维护配置、编辑会话和自动重读决策。

## 配置与平台接口

桌面主进程使用共用 `setting.toml` 保存编辑器配置。共同存储位置、读写责任与启动分区由 [ADR-004](../4-feat-startup-layout/adr.md#共用设置来源)维护。本文只维护 `[editors.markdown]` 和 `[editors.html]` 的编辑器描述，不再建立单独配置文件。

应用定义文件类型与编辑器描述格式，平台验证并启动应用条目、可执行程序或应用包。编辑器更新只修改自己的分区，保留其他配置。描述保存绝对路径 `program`；KDE/Linux 的新选择保存 `.desktop` 应用条目，已有可执行路径配置继续可用。

文件不存在表示尚未配置。格式损坏、应用不可用或写入失败必须显示错误，不能静默换成系统默认程序。选择编辑器后先验证必要信息，再持久化。首版只保存当前平台可用的配置，不增加跨设备配置迁移。

KDE/Linux 通过原生 `KOpenWithDialog` 选择已登记的应用，不以文件浏览器替代应用列表。桥接程序验证 `.desktop` 可读性与应用类型，不要求执行位。启动使用 `gio launch`，系统负责解释 `Exec` 的既有参数与占位符，Reader 不自行拆分命令，也不修改 MIME 默认关联。设置与临时“打开方式”使用同一选择接口。

文件路径作为独立参数传给平台启动函数，不拼接成 shell 命令。普通可执行程序使用无 shell 的参数数组；已识别的 VS Code 启动方式由平台添加 `--wait`。macOS 应用包等系统方式由平台实现负责。

Electron 的 `shell.openPath` 按系统默认方式打开文件，并不选择用户配置的编辑器。因此，它不能单独实现默认编辑器功能。[Electron shell 文档](https://www.electronjs.org/docs/latest/api/shell#shellopenpathpath)说明了这个行为。

在 ADR-001 的边界下，原生对话框选择程序/应用，平台的 `validateEditor` 验证路径，`startEditor` 启动指定文件并返回 `completion` 与 `waitForFile`。主进程保存配置、判定目标与管理重读，平台实现只处理系统启动和可观察的完成事件。

## 交互与目标

workspace 文件中击与“在配置编辑器中打开”共用一个应用动作。工作区目标由受验证的根目录和规范路径确定。标签右键目标由文档 id 确定。右键非活动标签时不切换活动标签来间接选择文件。

标签中击继续调用关闭动作，与显式关闭按钮和关闭命令一致，不调用编辑器。中击关闭非活动标签时保持当前活动标签。“打开方式…”只为本次选择编辑器；设置弹窗中的选择才修改持久配置。取消选择不产生编辑会话。

移动端删除本条目的编辑器能力。共享菜单按能力省略编辑器项，Android 设置不展示编辑器分区，也不注册原生编辑器启动接口。仅隐藏按钮不足以满足该范围限制。具体移动端范围由 [条目 5](../../open/5-feat-android/issue.md)维护。

新 IPC 请求继续通过主进程校验调用来源。文档 HTML 不能访问编辑器能力。沿用现有工作区授权和文档登记检查，不把它扩大成任意路径执行接口。

## 编辑会话与重读

编辑会话表示一次外部编辑请求。每次请求先建立目标路径的变化监听，再启动编辑器。应用维护路径到已打开文档 id 的关系，同一路径的全部标签共享更新来源。平台完成事件只表示它实际观察到的范围。

| 平台报告 | 应用行为 | 产品边界 |
| --- | --- | --- |
| 可等待本次文件会话结束 | 保存时更新，会话结束时再重读一次 | 可以用于验收 R3.4，但必须有编辑器实测证据 |
| 只能等待新建应用进程退出 | 保存时更新，已证明独立进程对应会话时才使用退出事件 | 复用现有进程时不能把启动器退出当成完成 |
| 只有系统分发结果 | 保存时更新，Reader 恢复焦点时重查 | 可使用该编辑器，严格关闭检测仍未满足 |

不扫描全系统进程，也不按编辑器窗口标题猜测完成。平台选择器允许打开已有应用，但“可打开”与“可等待”分别报告。首个严格完成方案必须用真实编辑器证明等待模式，不能只用测试进程证明所有编辑器都可等待。

应用监听目标的父目录，并只处理关联文件。它同时在可验证的会话完成和 Reader 恢复焦点时重读或核对快照。Linux/macOS 上，直接监听文件会绑定原 inode；删除重建后不会自动监听新对象。Node 官方文档明确记录此限制。[Node 22 文件监听说明](https://nodejs.org/docs/latest-v22.x/api/fs.html#inodes)是父目录监听决策的依据。

目录事件可能合并或没有文件名。应用重新核对该目录中的已登记目标，不推断未保存内容。连续事件合并为一次短延迟读取。延迟值由真实保存测试确定，不增加用户配置项。读取结果按目标版本顺序提交，较早完成的请求不能覆盖较新的快照。

原子替换期间的短暂不存在可以触发有限重试。持续删除、改名、权限错误或非 UTF-8 不能无限重试。应用显示明确错误并保留最后成功快照。监听建立或运行失败也显示错误，不静默降级成成功。

每次成功读取统一更新文档快照与原始 bytes，然后按既有 id 通知全部仍打开标签。后台标签不抢焦点。HTML 生成新的 `pageUrl`，沿用当前隔离策略。未打开的工作区文件不会因编辑完成自动新建 Reader 标签。

当某条路径没有打开标签和在途编辑请求时，释放它的监听。文档关闭后的完成事件不重新登记旧 id。Reader 退出时释放监听和回调，不终止用户编辑器。

## 标签与视图状态

自动重读保留标签 id、有效根目录和活动标签。Markdown 重建目录和查找结果。阅读位置在新内容可用后按原位置恢复，并限制到新的有效范围。HTML 替换 iframe 快照后重新加载，不绕过沙箱取得页面内部状态。

“另存为”仍保存最新成功读取的原始 bytes。Reader 不回写编辑器的内容，不同步未保存缓冲区，也不提供编辑器内嵌界面。

## 取舍与待验证项

单纯等待启动器退出不能满足 B3.1。只监听旧文件不能满足 B3.2。因此，会话能力与文件变化都进入方案。Reader 恢复焦点的重查处理遗漏通知，但不冒充关闭事件。

首版采用保存自动刷新与焦点重查；已确认的 VS Code 文件等待通过 `--wait` 接入，普通启动器退出不触发关闭重读。Linux 的真实编辑器等待证据保留在原 probe 记录；macOS 与 Windows 的真实编辑器行为仍等待原生验证。
